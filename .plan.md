## 1. Goal
Expose the proven, vendored `agent-funds-gate` OFAC screen-before-transfer control as a Model Context Protocol (MCP) server over stdio, so a real MCP client can call one tool (`authorize_funds_transfer`) and get the GOVERNED gate's structured verdict — with two server-level fail-closed promises ("deny within a 90s deadline" and "any error denies") that the bare control does not provide. The server writes ZERO gate logic; the OFAC ordering decision lives only in the vendored control. Go-to-market wrapper around the already-proven control; not a new control, not a generic agent framework. Sibling discipline mirrors `~/agent-audit-packet` (vendor-and-wrap, pinned digests, anti-clone, zero-install, no-network, degrade if pytest absent).

## 2. Injection posture (external-content rule — binding, with a test)
The MCP tool-call arguments arrive from an MCP client that may itself be an untrusted/under-governed agent. Every argument is treated as DATA, never as instructions: arguments only populate the `subject`, `transfer_seq`, `required_sdn_version`, and `screen` values that are passed into `FundsGate.authorize(...)`. An argument can NEVER select a code path, name a module to import, evaluate a string, trigger a file write, a network call, or a spend. The server has no `eval`/`exec`/`__import__`-by-name path, opens no files for writing at runtime, and makes no network calls. A `subject` of `"__import__('os').system('rm -rf /')"` is just a string handed to the gate, which decides purely on the ordering invariant. This invariant is asserted by test (S16). If a future tool ever ingests email/web/README/posting content, that is a NEW design and must restate this section and add injection tests for it.

### 4.1 verdict.py (pure types, no gate import)
```
@dataclass(frozen=True)
class EvalRequest:
    subject: str
    transfer_seq: int
    required_sdn_version: str
    screen: dict | None          # plain data: {status, sdn_list_version, completed_seq, subject} or None
    deadline_s: float | None     # caller-requested budget; None -> default. Capped at 90 in the guard.

@dataclass(frozen=True)
class EvalVerdict:
    decision: str                # "ALLOW" or "DENY". ALLOW is ONLY ever read out of a real GateDecision (see anti-clone test V6).
    rule_cite: str | None        # gate DENY -> OFAC_CITE read from the decision; wrapper-level DENY -> None
    failing_assertion: str | None
    sdn_list_version: str | None
    evidence: dict               # carried through / annotated; never re-decides anything
```
Wrapper-level (server-owned) DENY assertions, NOT gate assertions: `evaluation_deadline_exceeded`, `evaluation_error`, `vendor_integrity_failure`. For these, `rule_cite=None` (the gate did not render them; misattributing the OFAC cite would be dishonest). Gate-rendered DENYs carry the real `rule_cite`/`failing_assertion` read out of the `GateDecision`.

SEAM rationale (and an honest limitation, stated not hand-waved): the deadline is enforced as a post-hoc elapsed check around an injectable clock and an injectable evaluator, so a test advances a FAKE clock to simulate a slow evaluation and asserts DENY-within-budget with NO real sleeping and NO threads. The inner evaluation is pure, synchronous CPU (a dict -> gate call), so it cannot be pre-empted mid-call; "deny within deadline" therefore means "if the work took longer than the SLA, its result is discarded and the server DENYs" — a bounded-report guarantee, not a pre-emptive kill. A preemptive thread/signal kill is deliberately NOT used (added nondeterminism + its own failure surface for a microsecond-scale pure call). The cap (`min(requested, 90)`) makes the SLA non-extendable by the caller. Mac-asleep behavior falls out for free: on resume `time.monotonic()` has advanced past the budget, so an interrupted call DENYs (fail closed).

### 4.6 TOOL inputSchema (JSON-Schema, hand-validated)
- `subject`: string, REQUIRED.
- `transfer_seq`: integer, REQUIRED. Reject Python bool (JSON true/false) as a type fault.
- `required_sdn_version`: string, REQUIRED.
- `screen`: object | null, OPTIONAL (default null). When an object: `status` (enum: "clear"|"hit"|"pending"|"error", required), `sdn_list_version` (string, required), `completed_seq` (integer | null, required), `subject` (string, required).
- `deadline_s`: number, OPTIONAL, must be > 0. Accepted but the guard caps the EFFECTIVE budget at 90 (the SLA is non-extendable; a request > 90 is not an error, it is silently capped — documented in README and CONTROL_INDEX).
- additionalProperties: false at the top level.

### 4.7 DENY-vs-error boundary (explicit, documented decision)
- A well-typed-but-unsafe scenario (the race, a HIT, a pending screen, a missing/null screen, a subject mismatch, a version mismatch) -> the gate DENYs -> a SUCCESSFUL `tools/call` result with `structuredContent.decision="DENY"`, `isError:false`. A DENY is NOT a JSON-RPC error and NOT `isError:true`.
- A protocol/argument fault (missing required arg, wrong JSON type, unknown status enum, unknown tool name, malformed envelope, unknown method, unparseable line) -> a JSON-RPC ERROR object. `isError:true` is reserved and, by the fail-closed design (the guard converts every internal error to a DENY verdict), is not set on a completed evaluation; both ALLOW and DENY are `isError:false`.
- Missing/null `screen` is NOT a protocol fault — it is a safe DENY (`screen_present`). Only `subject`/`transfer_seq`/`required_sdn_version` are required; their absence is -32602.

## 6. Polarity procedure (documented, run by writer then reviewer)
With `PYTHONDONTWRITEBYTECODE=1` and `find . -name __pycache__ -prune -exec rm -rf {} +` first:
1. Centerpiece: in evaluate.py flip the gate construction to `FundsGate(req.required_sdn_version, naive_mode=True)`. Run S4 -> it MUST go RED (race now ALLOWs). Restore -> S4 green.
2. Deadline: delete the `elapsed > budget -> DENY` block in guard.py. Run G1 -> RED. Restore -> green.
3. Fail-closed: delete the try/except-DENY in guard.py. Run G5 -> RED. Restore -> green.
4. Vendor drift: change one byte in a `vendor/agent_funds_gate/*.py` file. Run V1 -> RED. Restore -> green.

## 7. Failure modes — every one fails CLOSED
- Malformed JSON line -> serve() emits -32700 (id null), continues; never crashes, never ALLOWs. L2/L4.
- Unknown method -> -32601. S7.
- Bad/missing/wrong-typed argument, unknown tool, unknown status enum -> -32602; no gate call, no DENY-shaped success that could be mistaken for an evaluation. S9/S10/S12.
- Missing/null screen -> safe DENY ("screen_present"), isError false. S11/E4.
- Gate hands back a malformed-input DENY (e.g. non-int transfer_seq that slipped validation) -> the vendored gate already DENYs (`transfer_seq_invalid`/`screen_malformed`) and never raises; the verdict is read out unchanged.
- Inner evaluation raises -> guard converts to DENY ("evaluation_error"); never propagates, never ALLOWs. G5.
- Inner evaluation exceeds the (<=90s) budget, or the Mac sleeps mid-call (monotonic clock jumps past budget on resume) -> DENY ("evaluation_deadline_exceeded"). G1/G2/G6.
- Vendored gate drifts from its pinned SHA -> startup refuses to serve (EXIT_VENDOR_DRIFT) AND any tools/call on a vendor_ok=False state DENYs ("vendor_integrity_failure"). V1/V7/S14.
- Empty/partial request (missing id with a non-notification method, or `{}`) -> -32600; a true notification (no id) -> None (no response). S2/S8.
- Crash mid-run / unhandled fatal -> main returns non-zero; serve.sh (`set -euo pipefail`, `exec`) propagates non-zero; the shell never sees 0 on a crash. No daemon, no scheduler, no persisted state, so an interrupted process leaves no partial "served" signal.
- No file writes, no network, no spend anywhere at runtime (injection-safe). S16.

## 8. Exit-code / error contract (precise)
Server process (`serve.sh` / `python3 -m agent_eval_gate.server`):
- `0` — clean shutdown on stdin EOF after serving.
- `4` (EXIT_VENDOR_DRIFT) — vendored-gate integrity check failed at startup; the server REFUSED to serve.
- `5` (EXIT_INTERNAL) — unhandled fatal before/around the loop (fail closed; never 0 on a crash).
Demo (`demo.sh`): `0` — the scripted session ran and the race DENYed + the safe case ALLOWed as asserted by the demo itself; non-zero — the demo's own assertions failed (the gate did not hold). The demo is a self-checking acceptance gate, not just a print.
JSON-RPC error mapping (inside the served protocol, not the process exit): `-32700` parse error, `-32600` invalid request, `-32601` method not found, `-32602` invalid params. A tool DENY is a successful result (`isError:false`), never an error object.
